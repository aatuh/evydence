# Backlog Issue Labels

Use these labels for issues created from the 9/10 execution backlog. Labels
organize work; they do not prove implementation, validation, or external
evidence.

| Label | Use |
| --- | --- |
| `epic` | Parent issue for one EVY epic. |
| `P0`, `P1`, `P2` | Delivery priority from the backlog. |
| `security` | Trust, cryptography, authorization, privacy, or abuse resistance. |
| `persistence` | PostgreSQL, migrations, transactions, idempotency, or recovery. |
| `api` | HTTP, OpenAPI, compatibility, or SDK contract work. |
| `sdk` | Go, TypeScript, or Python client work. |
| `docs` | Documentation, examples, or user workflow work. |
| `operations` | Deployment, observability, backup, release, or runtime work. |
| `external` | Needs maintainer, provider, reviewer, or design-partner proof. |
| `blocked` | Cannot proceed until the issue states the exact prerequisite. |
